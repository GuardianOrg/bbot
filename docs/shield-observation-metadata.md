# Shield observation metadata

- LeakLookup/DeHashed provider date fields are database indexing timestamps, never inferred breach dates. Valid dates travel in `leak-indexed-at-<epoch>` tags, separate from `db-<source>` tags. Missing dates remain unknown. Dated observations can refresh existing Sentry leak history without creating new exposure identities.
- Repository secret fingerprints remain stable. A newer committer timestamp from a scanner-reported matching commit can pass deduplication for Sentry to merge into `secretLatestCommitAt`. Missing commit evidence never borrows HEAD's date. This does not perform an exhaustive newest-containing-commit search or validate credentials.
- HTTP response collection enables technology detection; Sentry persists observed stack/provider metadata in existing technology arrays.
- `host_reputation` uses MalwareWorld manifest-directed shards for domains, IPv4 addresses and ranges, phones, apps, hashes, certificates and CVEs. Extra indicator types come from already-observed metadata; no new targets or files are probed. Hash input also checks certificate feeds. Parent domain matching respects public/private suffix boundaries, and IPv4 matching includes containing CIDRs.
- Every category and reference is retained, with match specificity and available feed/source freshness. Explicit threat categories score 80 at the asset level. Context categories and CVE/KEV intelligence alone do not label an asset malicious. Zero is absence of a matching threat, not a safety guarantee or company risk score. Whitelist entries do not erase conflicting threat matches. Feed failures remain errors. Shard cache is bounded to 64 entries/15 minutes.
- IPv6 is unsupported by current MalwareWorld feeds. Normal lookups no longer call legacy reputation APIs; their helper methods/configuration remain for compatibility.
- `tests/fixtures/malwareworld-contract.json` is mirrored in Sentry's `tests/offchain/fixtures/`. Keep both fixtures and implementations aligned when changing the contract.
- No testssl default activation, exploitation checks, credential validation or cloud-exposure discovery is included. Do not expose raw secret/email evidence in public summaries.

Review hardening: domain normalization uses nontransitional IDNA, matching Sentry. Missing HTTP shards (including 404), invalid CIDRs and malformed matching records are errors, not clean verdicts. Empty data must be served explicitly; missing-shard semantics require an upstream completeness contract. Immutable range shards are validated and indexed once, with at most 64 retained indexes. Numeric Apple store IDs and IPv6 inputs are explicitly unsupported coverage, not clean assessments.
